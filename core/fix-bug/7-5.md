## 🧾 1. Customer Order Detail Page

### 🐛 1.1 Stepper State — "Delivered" Not Fully Green

**Problem:** When order status = `Delivered` (تحویل داده شده), the stepper doesn't mark all previous steps as completed/green.

**Root Cause (Suspected):** Stepper likely compares `currentStep === stepIndex` instead of `currentStep >= stepIndex` for the "completed" state, OR the final "Delivered" status isn't mapped to the last stepper index.

**Files/Components to Modify:**
- `components/order/OrderTrackingStepper.tsx` (or equivalent stepper component)
- Status-to-step mapping utility (e.g., `utils/orderStatusMap.ts`)

**Plan:**
- Ensure status enum `DELIVERED` maps to the **final step index**.
- Update the step rendering logic so all steps with `index <= currentStepIndex` receive the `completed` (green + checked) state.
- Add explicit handling: if `status === DELIVERED` → force all steps to `completed`.

## 🛒 3. PDP Sticky CTA & Variant State Sync

### 🐛 3.1 Variant Context Switching — CTA Counter Doesn't Update

**Problem:** Adding 2 Red → switching to Black → CTA still shows "2" instead of Black's quantity.

**Root Cause:** Sticky CTA reads total product quantity in cart, not the currently-selected-variant quantity.

**Files/Components to Modify:**
- `components/pdp/StickyCTA.tsx`
- `hooks/useCartQuantityForVariant.ts` *(new or updated hook)*

**Plan:**
- Replace `cart.getQuantityByProductId(productId)` with `cart.getQuantityByVariantId(selectedVariantId)`.
- Subscribe CTA counter to **selected variant state** (reactive).
- On variant change → recompute counter from global cart based on new variant ID.
