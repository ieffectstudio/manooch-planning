### Detailed Problem Descriptions & Functional Specifications

#### 1. Portal — Remove "National Code" from Super Admin & Seller Registration
* **Current State & Problem:**  
  When a Super Admin or Seller registers or completes their onboarding in the Portal, the form requires (or presents an input for) their **National Code** (*کد ملی* / National ID number). This creates unnecessary friction during onboarding and collects personal identification information that is not essential at this stage.
* **Required Product Behavior:**  
  * Completely remove the **National Code** field from the registration and onboarding workflows for both Super Admin and Seller roles in the Portal.
  * Ensure that registration forms can be successfully submitted and validated without requiring a National Code.

---

#### 2. Portal / Admin / Storefront — Role Separation for Super Admins
* **Current State & Problem:**  
  A user authenticated as a **Super Admin** in the Portal is currently treated as automatically authenticated within individual store Admin Panels (even if they do not own or manage a store) and on the customer-facing Storefront. This blurs the line between platform-level management and store-level user accounts, leading to confusing permissions and interface states.
* **Required Product Behavior:**  
  * **Strict Role Isolation:** Being logged into the Portal as a Super Admin must not automatically grant authenticated customer status on a Storefront or store-owner status in an Admin Panel.
  * **Explicit Registration / Login Required:** If a Super Admin wants to create a store or shop as a customer on a storefront, they must explicitly register or log into that specific store role.
  * An admin panel without an associated store account should prompt the user to register/create a store rather than showing an authenticated empty state.

---

#### 3. Storefront — Customer Profile Page is Empty / Not Showing Up
* **Current State & Problem:**  
  When a customer navigates to their **Profile Page** on the Storefront, the page content fails to render, appearing completely blank or empty.
* **Required Product Behavior:**  
  * The Customer Profile page must reliably render the customer’s account details and standard sections (such as Personal Information, Address Book, Order History, and Account Settings).
  * Any edge cases where user data is incomplete or still loading should display an appropriate loading indicator or user-friendly placeholder message rather than an empty page.

#### 5. Admin Panel — Remove "Followed Store" from Admin Hamburger Menu
* **Current State & Problem:**  
  The Hamburger Menu in the **Admin Panel** includes a menu item labeled **"فروشگاه دنبال کردید"** (*Followed Stores / Stores you follow*). Following a store is a shopper/customer feature and has no place in the merchant's administrative workspace.
* **Required Product Behavior:**  
  * Remove the **"فروشگاه دنبال کردید"** menu item entirely from the Admin Panel Hamburger Menu.
  * Ensure this feature remains available only where appropriate (in the customer-facing Storefront experience).

#### 6. App-wide — Intermittent Client-Side Error Screen During Navigation
* **Reference Image:** `manooch-planings\core\bugs\error.png`
* **Current State & Problem:**  
  While browsing or surfing across the application, users intermittently hit the unexpected error screen captured in `manooch-planings\core\bugs\error.png`. As noted in the report, this manifests as a frontend interface crash (likely related to client-side page hydration discrepancies or schema/data shape mismatches) rather than a backend server failure.
* **Required Product Behavior:**  
  * Client-side navigation across the application must be resilient so that temporary timing differences or data structure variations do not crash the entire page view.
  * If a page or component encounters unexpected data during rendering, the application should handle it gracefully (e.g., displaying a fallback state or retry option) instead of showing the fatal full-screen error depicted in `manooch-planings\core\bugs\error.png`.

#### 7. Banners — Clickable URL Support & Open in New Tab
* **Current State & Problem:**  
  Promotional banners currently do not allow administrators to attach clickable destination links, or they navigate away from the current page within the same tab when clicked.
* **Required Product Behavior:**  
  * **Link Attachment:** Administrators must be able to assign a target web URL to any banner.
  * **New Tab Navigation:** When a user clicks on a banner that has an associated link, the target URL must open in a **new browser tab**. This ensures that customers are not directed away from their shopping cart or store session.

---

#### 8. Reviews Feature — Replace Like/Dislike with a Heart-Only ("Like") Action
* **Current State & Problem:**  
  The current customer review component features both "Like" (thumbs up / hand icon) and "Dislike" (thumbs down / hand icon) voting options.
* **Required Product Behavior:**  
  * **Remove Dislike Functionality:** Completely eliminate the "Dislike" button, any dislike counts, and any negative review voting behavior from the UI and product flow.
  * **Heart Icon for Like:** Replace the existing hand icons with a single **Heart icon** to represent "Like / Helpful."
  * Users should only be able to toggle a positive heart on or off for a review.

---

#### 9. Admin Dashboard — Remove QR Code from Plugin Grid View
* **Current State & Problem:**  
  In the main Plugin Management dashboard, each plugin card in the grid/list view currently displays a QR code. This creates unnecessary visual clutter on the overview page.
* **Required Product Behavior:**  
  * Remove the QR code visual element from plugin cards on the **Dashboard Plugin Grid / List view**.
  * Keep any QR codes or direct sharing links intact in other detailed views or dedicated plugin settings modals where they are actually used.

---

#### 10. Plugin Management — Confirmation Bottom Sheet Before Deactivating a Plugin
* **Current State & Problem:**  
  Currently, when an administrator toggles off an active plugin on the Plugin Management page, the plugin is deactivated immediately without warning. Accidental clicks can disrupt critical store features (e.g., payment gateways, shipping calculators, or marketing tools).
* **Required Product Behavior:**  
  * **Confirmation Prompt:** When an administrator toggles a plugin from **ON to OFF**, immediately present a **Confirmation Bottom Sheet** (or confirmation modal).
  * **User Action Required:** The bottom sheet should clearly ask the user to confirm whether they want to disable the plugin, with explicit "Confirm / Disable" and "Cancel" buttons.
  * The plugin's active status must only change after the user confirms the action in the bottom sheet. Toggling a plugin from **OFF to ON** should remain immediate (or follow existing enablement steps).

---

#### 11. Toast Notification Widget — Resize, Touch-Blocking Fix, and Top Positioning
* **Current State & Problem:**  
  * **Size & Layering:** The current toast notification is visually bulky and blocks interaction with elements underneath it. Users report that the area around or below the toast remains clickable/touch-sensitive in unintended ways, or conversely blocks clicks to the page content behind it.
  * **Positioning:** The toast currently appears at the bottom of the screen, where it frequently obscures bottom navigation bars or primary action buttons.
* **Required Product Behavior:**  
  * **Compact Dimensions:** Reduce the overall dimensions (height and width footprint) of the toast banner so that it presents information concisely without covering significant screen area.
  * **Non-Blocking Interaction:** Ensure the toast notification area only captures clicks/touches on the toast card itself (such as a close button or action link), allowing users to freely click or interact with page content around and beneath the alert.
  * **Top Positioning:** Change the display position from the **bottom** of the viewport to the **top** of the viewport.
  * **Vertical Spacing:** Maintain a clear vertical margin of **40 to 80 pixels from the top edge** of the screen so that the toast floats cleanly below top navigation headers without overlapping them.
